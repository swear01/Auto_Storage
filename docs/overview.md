# Overview

## What This Is

**Auto Storage**（技術 mod ID：`auto_storage`；Java package：`com.swear.autostorage`；repository：`Auto_Storage`）— NeoForge 1.21.1 的一站式儲存 + 魔法合成 mod。公開 listing、display name、GitHub repository、本機 checkout、registry namespace、設定/存檔 key 與 0.3.0 jar basename 全部統一使用 Auto Storage / `auto_storage`。

0.3.0 是明確的 breaking identity release：不提供 0.2.x world、registry、config、command、addon ID 或 SavedData migration，也不保留舊 alias/fallback。升級者必須建立新世界，並把 0.3.0 當成不同技術 identity；不得同時放入 0.2.x 與 0.3.x jar。

玩家用終端儲存與取用物品、流體、能量、氣體和addon資源；有限 Storage Units提供種類容量，Creative Storage Unit則明確提供無限種類。Crafting Terminal把可執行配方、確定性Transform，以及Processing/Instant Stations放在四個分開頁面。

概念源自 **Terraria 的 Magic Storage**(無限容量、配方書操作);NeoForge 的儲存網路 / grid UI / 物品處理等**技術模式參考 Refined Storage 2** 原始碼(見 `docs/notes.md`)。

## Key Concepts / Domain

- **Storage Core** — 網路中樞，所有計算（容量、合成、能量）都在 Core；Unit 只提供空間。永久資料從建立時起由 overworld `data/auto_storage_core_storages.dat` 的 `CoreStorageRepository` 擁有，Core 所在 chunk 只保存 `storageId` 與 `storageSchema`。庫存以每段最多 63 種的任意多段格式持久化，63 不是玩家容量上限。破壞、爆炸、創造模式或 Wrench 拆除含資料 Core 時，掉落物只攜帶一次性 recovery UUID 與摘要，放置時把同一 storage/network record 移到新 Core，不複製 payload；指令或其他模組直接移除非空 Core 時也會先建立 ownerless recovery，避免留下無法領回的孤立 record。玩家可用 `/auto_storage recover_core` 重發自己的最新未 claim capability；operator 可用 `/auto_storage recover_core ownerless` 重發沒有玩家 owner 的最新 recovery。缺少、毀損、packed 或重複 attachment 一律 fail closed 並拒絕終端/自動化操作，不會製造空白 replacement。本次早期開發格式不遷移舊 inline Core NBT 或舊 recovery snapshot。
- **Storage Unit** — 六個有限 Tier 的儲存方塊獨立、不可逆、可並聯不限數量；T1→T6 以 copper cell、iron brace、gold/lapis lattice、diamond/quartz cross、prismarine/ender halo、netherite/amethyst crown 逐級增加 ornament complexity。`creative_storage_unit` 只由創造物品欄/指令取得、沒有配方/庫存/生成能力，en_us/zh_tw item tooltip 也明確標示無限種類且不生成物品；有效且目前已載入的單 Core 網路只要連上一個就以 explicit unlimited 種類容量運作，多個效果相同。移除或卸載只回到有限超額規則，不刪既有物品。
- **Addon SDK / compatibility modules** — 外部NeoForge addon用一個`AutoStorageAddon.register(...)`接上descriptor、exact recipe family、typed kind、block/container transfer、Transform provider、existing-station variants與bounded capability/reload hooks；`AutoStorageCapabilityApi`只交付公開typed handler，不暴露Core/Bus block entity。需要exact client glyph時，client setup可用generic `TerminalResourceRendererApi`，其公開API bytecode不連結client class。全部仍走granular custom registries。Bundled integrations位於target-isolated source sets，直接只對API jar與各自target dependencies編譯；runtime metadata要求至少一個target mod ID並在classload前逐一檢查，同一個player jar內沒有central per-mod dispatcher或silent fallback。公開release另附API/sources/Javadocs；完整契約見[`addon-development.md`](addon-development.md)。
- **配方進程 / 指南** — T1 改以黑色混凝土粉末、銅、紅石與木桶製作，不再要求紫水晶；Core 與 T1–T6 依序引入黑曜石、玄武岩、鑽石/史萊姆、海磷晶/蜂蜜與獄髓。Patchouli 的雙語「配方總覽」集中顯示所有 Auto Storage 配方，每個配方只出現一次。
- **工具與終端進程** — Wrench 是 Brush + Tripwire Hook 的廉價建設工具。Storage Terminal 保持起步期但加入紅石火把控制件；Crafting Terminal 以金、銅、紅石和工作台成為早中期升級；Remote Terminal 再要求終界珍珠、黑曜石與指南針，作為較晚取得的移動能力。指南書本身註冊為 `auto_storage:guide_book` 並可合成。
- **Transforms and Stations** — Fuel、Brew、Axe、FE、Mana與addon資源都保存於Core的同一typed ledger。Transform頁把一個明確input以×1/×8/×64/Max轉成typed資源；輸入與amount strip都留在上方，Auto只列可用用途，不會自行消耗，每張card直接標示來源或所需station/work，失敗時input、資源與輸出保持原狀。Stations頁只分Processing與Instant：Processing按exact installed variant的live rational rate累積work，可安裝到`Integer.MAX_VALUE`並顯示installed aggregate/rate/work；Instant每descriptor最多一台，只解鎖配方且不顯示installed數量或work。兩區都有獨立前後頁與滾輪；`All`與搜尋結果中的未安裝代表物明顯變暗，已安裝物保持原始亮度；非空搜尋才合併stations，Processing最後一列不足欄數也保持固定欄寬並靠左靠上，inventory旁status panel只顯示type capacity且不隨hover重複資訊。物品hitbox保留exact機器的原生tooltip；Processing數值hitbox使用server同步的logical family名稱與aggregate rate，不再把Crusher、Energizing Rod、Furnator等不同資源全部叫做`Station Work`。Furnace cooking time、燃料burn time、工具耐久與optional-mod provider的recipe/config是數值真值；Botania Elven Trade也會消耗runtime exact Mana。所有mutation只在server，client只接同步。

- **Typed-resource Core** — Item、fluid、NeoForge Energy、optional Mekanism chemical、optional Botania Mana、optional Ars Nouveau Source與addon kinds現在共用一個server-owned `StorageResourceLedger`；`ItemKey`只保留exact-item bridge，舊segmented item NBT是save/load相容邊界而非第二個live map。公開`auto_storage:resource_kind`、`resource_block_strategy`與`resource_container_strategy` registries，加上`StorageResourceKey`、`StorageResourceTransaction`與generic block capability，形成不授予任意Core callback的addon邊界。Storage/Crafting Terminal以代表物列出non-item exact key/long amount，並可在cursor上用一個supported fluid/FE/chemical/Mana/addon container原子存取；stacked container只處理一個，result必須能精確替換cursor或放入玩家背包，否則Core與玩家狀態整筆不變。icon不可被當物品抽出。Creative容量對全部kind無限；Bus主動/被動路徑支援generic與native typed endpoints。`deterministicResources` family可宣告1–81個exact consume/catalyst/tool inputs與多個primary/remainder outputs，所有Core item/non-item delta以同一transaction simulate→commit。Addon handler必須simulation無副作用、回傳`0..requested`且execute mutation精確等於回傳值；binary-incompatible optional bridge直接明確失敗，不silent fallback。Mekanism CI只驗一個代表版本，不建立多版本承諾；其他版本問題由使用者回報。External-machine send-and-wait仍不屬於本mod，multi-step planner仍是後續。完整契約見 [`typed-resource-storage.md`](typed-resource-storage.md) 與 [`recipe-family-api.md`](recipe-family-api.md)。
